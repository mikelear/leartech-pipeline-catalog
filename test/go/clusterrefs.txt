# Task files that still declare a jx-cluster-config keyRef, with the reason each one does.
#
# Format: <path>|<why it is not yet covered by sp-variables>
#
# THE TARGET IS ZERO. The step that writes .jx/variables.sh is the one place a VALUE is read:
# go/spvariables' clusterValues reads jx-cluster-config inside the binary, so the value reaches
# every later step as a file. Two groups are recorded below.
#
#   TRANSITIONAL — the sp-variables STEP itself. It declares env because the checkers image is
#   a pinned tag Renovate moves, and the tag that predates the in-binary read cannot read the
#   ConfigMap. The env is what makes the step work either side of that release, and every line
#   in this group deletes at once when the pin reaches an image that has the read.
#
#   LABELS — steps that read ${CLUSTER_ID:-} to name the cluster in a PR comment. These need
#   the value, not the read, and they retire when prpost resolves the cluster from the file.
#
# WHAT REMOVES ONE OF THESE LINES: make the step stop reading the variable. Either
#   (a) `. .jx/variables.sh` at the top of the report script (the file is on the workspace by
#       then), or
#   (b) `prpost` resolving the cluster from the file itself, so the flag and the shell
#       interpolation both disappear.
# (b) removes the whole class; it is the change this file exists to make visible.
#
# This list may only SHRINK. A file not listed here must not declare the keyRef (the check
# fails), and a line whose file no longer declares it must be deleted (the check fails) — the
# same ratchet as test/go/orphan_tools.txt, for the same reason: a guard nobody prunes stops
# describing the tree.
